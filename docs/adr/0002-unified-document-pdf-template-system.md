# ADR-0002: Unified Document & PDF Template System Architecture

- **Status:** Accepted
- **Date:** 2026-08-17
- **Decision maker:** DivineKart platform architecture team

## Context

DivineKart requires a comprehensive PDF document generator (waybills, transit memos, receipts, e-bills, payment receipts, tax invoices) integrated with an admin drag-and-drop template builder, dynamic `{{key:value}}` placeholders, multi-channel dispatch (Email attachments + WhatsApp file sends), and binding to workflow pipeline stages (BRM subscription renewals, order placement/fulfillment, payment capture/refund).

Previously:
- Invoices/waybills were rendered only as print-ready HTML in browser (`backend/src/lib/invoice.ts`), with zero server-side PDF library.
- Email notifications were logged to console (`backend/src/lib/brm-notify.ts` seam).
- An email template store (`backend/src/modules/email-template/`) was partially built.

## Decision

We establish a **Unified Document & PDF Template System**:

1. **PDF Rendering Stack**: Server-side HTML→PDF via `puppeteer` (v25+) using Alpine's system `chromium` package (`/usr/bin/chromium-browser`) to run inside the `node:24-alpine` container without downloading glibc Chrome binaries. Shared singleton browser instance with `--no-sandbox --disable-setuid-sandbox --disable-dev-shm-usage` flags.
2. **Unified Template Store**: Generalize `email_template` into a single template store supporting `format: pdf|email|html` and document kinds (`invoice`, `waybill`, `transit_memo`, `receipt`, `e_bill`, `payment_receipt`, `custom`) with page geometry (format, orientation, margins), design JSON, exported HTML, and `{{key:value}}` placeholder catalogs.
3. **Immutability & Storage Strategy**:
   - **Tier 1 (Pipeline Emitted Documents)**: When a document is generated by a pipeline event, save the resulting PDF permanently via Medusa's File module (S3/local uploads) and store the immutable file URL and HTML snapshot on the entity metadata.
   - **Tier 2 (Drafts / Previews)**: On-the-fly rendering for admin builder previews and draft links.
4. **Admin Builder UX**: Multi-mode editor in `@medusajs/ui`:
   - Sectional Block Builder (`dnd-kit`) for dynamic multi-page documents (invoices, receipts).
   - Absolute Positioning Canvas for fixed single-page labels/waybills.
   - Hybrid HTML/CSS Code Editor with live split-screen PDF preview.
5. **Data Placeholders**: Built-in typed catalogs for Logistics (`{{logistics:*}}`), Payment/E-Bill (`{{payment:*}}`), Order/Customer, and Subscription/BRM, plus dynamic resolution of arbitrary keys from `order.metadata` and `subscription.metadata`.
6. **Pipeline Triggers**: Event-Driven Medusa Subscribers (`order.placed`, `payment.captured`, `brm.subscription.*`) for background async processing, custom Medusa Workflow steps (`generateDocumentStep`) for synchronous pipelines, and manual Admin "Re-send / Download" overrides.
7. **Email Transport**: Nodemailer SMTP engine configured via Admin Settings UI (`divinekart_settings.smtp` blob) with provider presets (SES, SendGrid, Mailgun, Gmail), "Send Test Email" utility, and fallback to the console log seam when unconfigured.
8. **WhatsApp Attachment Dispatch**: Direct PDF file transmission via OpenWA/WAHA `sendFileFromUrl` with text captions containing an authenticated download-link fallback, and background job retries on gateway disconnection.
9. **Versioned Document Issuance**: Every pipeline emission creates an immutable **document version** (per order/subscription + document kind). Re-generations (template edits, reprints) append new versions; **all versions stay retrievable** for the same bill/receipt/quote/waybill/invoice. Files persist through Medusa's File module backed by **MinIO (S3)** when configured, with configurable TTL cleanup and regenerate-from-snapshot fallback.
10. **Access Model**: Customer downloads require customer authentication by default; admins preview/download any document; **expiring signed URLs** are generated for sharing contexts (WhatsApp caption links).

## Consequences

- Server-side PDF generation is fast, reproducible, and pixel-equivalent to browser printing.
- Docker build includes Alpine's `chromium` + Noto fonts (`font-noto-sans font-noto-sans-devanagari`). QEMU arm64 build timing is monitored against CI 30-min limits.
- Issued tax/shipping documents are legally immutable; template changes never retroactively alter past documents.
- Single admin surface manages both document templates and email templates under unified `{{key:value}}` placeholder logic.
- E-bill renders a verification QR (order/payment reference) always; GST IRN fields render only when present in metadata — statutory IRN filing remains out of scope.
- A `quote` document kind joins the seed gallery as a low-cost addition (shared invoice layout).
